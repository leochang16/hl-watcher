# HL Position Watcher

監控多個 Hyperliquid 地址，**開倉 / 平倉 / 反手 / 減倉** 時推播到 LINE。

篩選標準（排除量化/做市）：月成交量÷淨值在 5–150 倍、成交筆數 < 100 筆/天、持倉集中且單方向、本月之前已獲利。

## 運作方式

每 5 分鐘抓一次每個地址的 `clearinghouseState` 持倉快照，和 `state.json` 做差分。

- **不逐筆推 fill** — 巨鯨單次動作會拆成 8+ 筆成交，逐筆推會洗版。
- 多個地址同時有事件時，**合併成一則**推播（省 LINE 額度）。
- 平倉／反手／減倉時額外查 `userFills` 補上已實現損益。
- 名目 < `MIN_NOTIONAL`（預設 $5,000）的灰塵部位直接忽略。

只有**加倉**不通知（會靜靜抬高追蹤基準）。價格變動、未實現損益變化也不通知。

## 減倉偵測：用累積跌幅，不是單次跌幅

這是這個 bot 最容易做錯的地方。

如果只拿「這次」跟「上一次輪詢」比，巨鯨每輪只減 2%、門檻設 5%，就永遠碰不到門檻——倉位會無聲無息流乾，你收不到任何通知。

所以每個持倉都記兩個數：

- `peak`：出現過的最大數量
- `alerted`：上次發出減倉通知時的數量水位

判斷式是 `目前數量 < alerted × (1 - REDUCE_PCT%)`，觸發後把 `alerted` 下移到目前數量。這樣每再跌一階就通知一次，不重複洗版，也不會漏掉慢速流失。

實測：每輪減 2%、門檻 5%，會在第 3、6、9 輪觸發（累積 -5.9%、-11.4%、-16.6%）。

加倉時 `peak` 和 `alerted` 一起抬高，所以「先加後減」不會被誤判成減倉。反手時兩者都重設。

## 通知內容

每檔持倉都會列：名目、數量、**進場價、現價、漲跌幅、未實現損益、強平價（距現價百分比）**。
減倉另外列：此次減幅、自峰值累積減幅、峰值數量、剩餘名目。

現價是用 `positionValue ÷ szi` 反推的，不另外打行情 API——這樣算出來的價跟部位估值完全一致，不會出現「現價顯示 A、未實現損益卻用 B 算」的矛盾。

強平價距離為負代表在現價下方（多單），正代表在上方（空單）。不顯示槓桿倍數——強平價已經把槓桿的效果表達完了。

## 設定

| 位置 | 名稱 | 內容 |
|---|---|---|
| Variables | `HL_ADDRESSES` | 逗號分隔，每項 `地址=名字`（名字可略） |
| Secrets | `LINE_USER_ID` | LINE Developers › Basic settings › Your user ID |
| Secrets | `LINE_CHANNEL_ACCESS_TOKEN` | LINE Developers › Messaging API › Channel access token |

程式內可用環境變數調整（都有預設值，不設也能跑）：

| 變數 | 預設 | 作用 |
|---|---|---|
| `REDUCE_PCT` | `5` | 自上次警示水位再減這個 % 就通知 |
| `MIN_NOTIONAL` | `5000` | 低於此名目視為灰塵，忽略 |
| `DRY_RUN` | 空 | 設 `1` 只印訊息不推 LINE |

**這個 channel 同時被歐洲行程 bot 使用（webhook 指向 Cloudflare Worker），所以 token 不要按 Reissue** — 重發會把舊 token 廢掉，那隻 bot 會斷線。

## 增減追蹤地址

改 `HL_ADDRESSES` variable 就好，不用動程式。

- **新增**：直接加到清單尾端。下次執行會幫它建基準線並推一則「新增追蹤」，**不會**把它現有的倉位誤報成開倉。
- **改名字**：只改 `=` 後面那段，state 是用地址當 key，不會重建基準線。
- **移除**：從清單抽掉。`state.json` 裡的舊資料會留著但不影響運作。

不要手動刪 `state.json`——刪了下次執行會把所有地址的現有倉位全部當成新開倉重報一次，而且 `peak` 會從當下重新算，之前的減倉進度就丟了。

## 本機測試

```bash
export HL_ADDRESSES="0xbf732ea04197942783e34730ed6e0f6099575d58=滿槓老兵"
export DRY_RUN=1          # 只印訊息不推 LINE
rm -f state.json && python3 watcher.py   # 建基準線
python3 watcher.py                       # 第二次應顯示「無變動」
```

## 已知限制

- **延遲**：GitHub Actions 的 cron 最短 5 分鐘，高峰期常被延遲 5–15 分鐘，所以實際通知延遲可能到 20 分鐘。要壓到 1 分鐘得換 VPS 或 Cloud Run。
- **快進快出會漏**：兩次輪詢之間開完又平掉的倉位不會被偵測到。
- **看不到掛單**：只看已成交的持倉快照，所以掛在盤上還沒成交的單子看不到。
- **LINE 免費方案**每月推播上限（目前 200 則）是整個 channel 共用的。加了減倉通知之後則數會變多，但以這幾個地址的節奏還遠低於上限。
- **擁擠交易風險**：目前 ZEC新兵 和 滿槓老兵 都押 ZEC 多。他們同時減倉不是兩個獨立訊號，是同一個擁擠交易在出貨。
